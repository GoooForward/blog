# 0x00 常见文件IO操作(系统调用)

## 文件描述符

### 一、什么是文件描述符？

**文件描述符** 是一个非负整数，它是内核为了高效管理已被打开的文件所创建的索引。

你可以把它理解为：**一个指向 “已打开文件” 的 “指针” 或 “句柄”**。

当一个程序打开一个文件时，内核会在内部创建一个数据结构来记录这个文件的信息，包括文件的路径、当前读写位置、打开模式等等。这个数据结构被称为 **文件表项（File Table Entry）**。

为了让用户程序能够安全、方便地引用这个文件表项，内核不会把这个数据结构的地址直接暴露给用户，而是返回一个整数。这个整数就是 **文件描述符**，它指向内核中那个对应的文件表项。

后续对文件的所有操作（如读、写、关闭），程序都只需要提供这个文件描述符，内核就能通过它找到对应的文件表项，从而执行相应的操作。

### 二、文件描述符的特点

1. **非负整数**：文件描述符的值总是一个非负整数。
2. **唯一性**：在一个进程的生命周期内，每个文件描述符都唯一地对应一个打开的文件。
3. **进程私有**：文件描述符是**进程私有的**。也就是说，不同的进程可以拥有相同数值的文件描述符，但它们指向的是完全不同的文件表项（即不同的打开文件）。
4. **分配规则**：内核在分配文件描述符时，通常会从**最小的未使用的非负整数**开始分配。

### 三、标准文件描述符

在 Linux 中，当一个新进程被创建时（例如通过 `fork`），它会自动打开三个标准的文件描述符，分别用于标准输入、标准输出和标准错误输出。

| 文件描述符 | 符号常量 (stdio.h) | 用途                          | 对应的流 (stdio.h) |
| ---------- | ------------------ | ----------------------------- | ------------------ |
| `0`        | `STDIN_FILENO`     | 标准输入 (Standard Input)     | `stdin`            |
| `1`        | `STDOUT_FILENO`    | 标准输出 (Standard Output)    | `stdout`           |
| `2`        | `STDERR_FILENO`    | 标准错误输出 (Standard Error) | `stderr`           |

- **标准输入**：通常是键盘。
- **标准输出**：通常是终端屏幕。
- **标准错误输出**：通常也是终端屏幕，但它是一个独立的流，用于输出错误信息，这样可以和正常的输出分离开来（例如，将正常输出重定向到文件，而错误信息仍然显示在屏幕上）。

### 四、文件描述符的生命周期

1. **分配 (Allocate)**：
    - 当你调用 `open()`、`creat()`、`pipe()`、`socket()` 等系统调用成功时，内核会创建一个新的文件表项，并返回一个新的文件描述符。
    - 例如：`int fd = open("myfile.txt", O_RDONLY);` 如果成功，`fd` 会得到一个非负值，比如 `3`。
2. **使用 (Use)**：
    - 你可以将这个文件描述符传递给 `read()`、`write()`、`lseek()`、`close()` 等系统调用来操作文件。
    - 例如：`read(fd, buffer, sizeof(buffer));`
3. **释放 (Release)**：
    - 当你调用`close(fd)`系统调用时，内核会：
        1. 减少该文件表项的引用计数。
        2. 如果引用计数降为 0，内核会销毁这个文件表项，释放相关资源（如关闭文件、释放锁等）。
        3. 将这个文件描述符 `fd` 标记为 “未使用”，以便后续可以重新分配给其他新打开的文件。

**注意**：如果一个进程终止而没有关闭它打开的文件描述符，内核会在进程退出时自动关闭它们。但作为一个良好的编程习惯，你应该总是在不再需要文件时显式地调用 `close()`。

### 五、文件描述符与 `FILE` 指针的关系

在标准 C 库的 I/O 函数（如 `fopen`, `fprintf`）中，我们使用的是 `FILE *` 类型的指针（通常称为 “文件流”），而不是直接使用文件描述符。

它们之间的关系是：

- **`FILE` 结构体** 是 C 标准库在用户空间定义的一个数据结构，它封装了文件描述符以及其他信息，最重要的是 **I/O 缓冲区**。
- 当你调用 `fopen()` 时，它内部会调用 `open()` 系统调用获得一个文件描述符，然后创建一个 `FILE` 结构体，将这个文件描述符存入其中，并返回指向该结构体的指针。
- 后续的 `fread`, `fwrite`, `fclose` 等函数都是通过 `FILE` 指针找到对应的文件描述符，然后调用底层的系统调用来完成实际的 I/O 操作。`fclose()` 会在内部调用 `close()`。

简单来说：

```plaintext
你的程序 -> C库函数 (fopen, fread) -> FILE 结构体 (包含 fd) -> 系统调用 (open, read) -> 内核
```

你可以通过 `fileno(FILE *stream)` 函数从一个 `FILE` 指针获取其内部的文件描述符。反之，也可以通过 `fdopen(int fd, const char *mode)` 函数将一个已有的文件描述符封装成一个 `FILE` 指针。

### 六、示例：文件描述符的分配与重用

让我们通过一个简单的例子来看看文件描述符是如何工作的：

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int fd1, fd2, fd3;

    // 首次打开文件，会分配最小的可用fd，这里应该是 3
    fd1 = open("file1.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    printf("fd1 = %d\n", fd1); // 输出: fd1 = 3

    // 再次打开另一个文件，分配下一个最小可用fd，这里是 4
    fd2 = open("file2.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    printf("fd2 = %d\n", fd2); // 输出: fd2 = 4

    // 关闭 fd2
    close(fd2);
    printf("fd2 closed.\n");

    // 再次打开一个文件，内核会重用刚刚被关闭的 fd2 (值为 4)
    fd3 = open("file3.txt", O_CREAT | O_WRONLY | O_TRUNC, 0644);
    printf("fd3 = %d\n", fd3); // 输出: fd3 = 4 (因为 3 仍被 fd1 使用，下一个可用的就是 4)

    close(fd1);
    close(fd3);

    return 0;
}
```

这个例子清晰地展示了文件描述符的分配规则和重用机制。

### 总结

- **文件描述符** 是内核用来标识一个已打开文件的非负整数。
- 它是底层系统调用（如 `open`, `read`, `write`）操作文件的基础。
- 每个进程都有自己的一套文件描述符。
- 进程启动时会默认打开 `0`, `1`, `2` 三个文件描述符，分别对应标准输入、输出和错误。
- 文件描述符在不再使用时必须通过 `close()` 关闭，以释放资源并允许其被重用。
- 标准 C 库的 `FILE *` 指针是对文件描述符的一种封装，它提供了缓冲功能，让 I/O 操作更高效、更方便。





## open()

| -------- | ------------------------------------------------------------ |
| 头文件   | #include <sys/types.h><br />#include <sys/stat.h><br />#include <fcntl.h> |
| 函数原型 | `int open(const char *pathname, int flags, ... /* mode_t mode */);` |
| 功能     | 打开或创建一个文件，并返回一个文件描述符，用于后续的文件操作（如读、写、关闭等）。 |
| 返回值   | - 成功：返回一个非负整数（即文件描述符）。- 失败：返回 `-1`，并设置全局变量 `errno` 来指示错误类型。 |

------

| 参数名称   | 含义                                                         |
| ---------- | ------------------------------------------------------------ |
| `pathname` | 字符串指针，指向要打开或创建的文件路径（绝对路径或相对路径）。 |
| `flags`    | 整数类型，用于指定文件的打开方式和行为。常见取值如下：- **访问模式**：`O_RDONLY`（只读）、`O_WRONLY`（只写）、`O_RDWR`（读写）。- **创建 / 截断**：`O_CREAT`（文件不存在时创建）、`O_TRUNC`（清空文件内容）、`O_EXCL`（与 `O_CREAT` 配合，确保文件是新创建的，否则报错）。- **其他行为**：`O_APPEND`（追加模式）、`O_NONBLOCK`（非阻塞模式）等。 |
| `mode`     | 可变参数，仅当 `flags` 中包含 `O_CREAT` 时有效，用于指定新创建文件的权限（如 `0644`）。 |

| 函数原型 | `off_t lseek(int fd, off_t offset, int whence);`             |
| 功能     | 调整文件描述符 `fd` 对应的文件的当前读写位置。               |

# 0x01 标准IO操作（库函数）

标准 IO（Standard I/O）是一种抽象层，用于在程序和底层操作系统 I/O 接口之间提供一个标准化的、可移植的 I/O 接口。标准 IO 提供了对文件、终端、套接字等不同类型的 I/O 设备的统一访问接口。

## FILE指针

在标准库中，所有的文件 I/O 操作都通过 FILE 结构体来实现。标准库中预定义了三个文件流

stdin：标准输入流，通常关联着键盘输入。
stdout：标准输出流，通常关联着控制台显示器。
stderr：标准错误流，通常关联着控制台显示器，用于输出错误信息。

并且提供了一系列函数来处理这些文件流&FILE指针

## fopen()

- **功能简述**：
     以指定模式打开一个文件，并返回一个指向 `FILE` 对象的指针，用于后续的标准 I/O 操作。

- **头文件**：  

    ```c
    #include <stdio.h>
    ```

- **函数原型**：  

    ```c
    FILE *fopen(const char *pathname, const char *mode);
    ```

- **参数说明**：

    - `pathname`：指向以空字符结尾的字符串，表示要打开或创建的文件路径。
    - `mode`：文件打开模式字符串，例如 `"r"`（只读）、`"w"`（写入，清空）、`"a"`（追加）、`"rb"`（二进制读）等。

- **返回值**：

    - 成功时返回指向 `FILE` 对象的指针（可用于后续 I/O 操作）。
    - 失败时返回 `NULL`，并设置 `errno` 以指示错误原因。

- **注意事项**：

    1. 文件必须存在才能以 `"r"` 模式打开；否则 `fopen` 失败。
    2. 使用 `"w"` 模式会**截断已有文件为零长度**，或创建新文件。
    3. 模式字符串中可包含 `"b"`（如 `"rb"`）以明确二进制模式（在 Windows 上有区别，Unix/Linux 通常忽略）。
    4. 返回的 `FILE*` 必须通过 `fclose()` 关闭，避免资源泄漏。

## fclose()

- **功能简述**：
     关闭一个已打开的 `FILE` 流，刷新输出缓冲区（如有），并释放相关资源。

- **头文件**：  

    ```c
    #include <stdio.h>
    ```

- **函数原型**：  

    ```c
    int fclose(FILE *stream);
    ```

- **参数说明**：

    - `stream`：指向已打开的 `FILE` 流的指针。

- **返回值**：

    - 成功关闭时返回 `0`。
    - 失败时返回 `EOF`（即 `-1`），通常因缓冲区刷新失败（如磁盘满、I/O 错误）。

- **注意事项**：

    1. 调用 `fclose` 会**自动刷新输出缓冲区**（对输出流而言）。
    2. 关闭后，`stream` 指针变为**悬空指针**，不应再使用。
    3. 不要对同一 `FILE*` 多次调用 `fclose`，会导致未定义行为。
    4. 程序退出时标准库会自动关闭所有打开的流，但显式关闭是良好实践。



## fread()

- **功能简述**：
     从指定的 `FILE` 流中读取指定数量的元素（每个元素固定字节大小）到内存缓冲区，常用于二进制读取。

- **头文件**：  

    ```c
    #include <stdio.h>
    ```

- **函数原型**：  

    ```c
    size_t fread(void *ptr, size_t size, size_t nmemb, FILE *stream);
    ```

- **参数说明**：

    - `ptr`：指向存储读取数据的内存块的指针（通常为数组或缓冲区）。
    - `size`：每个元素的字节大小（如 `sizeof(int)`）。
    - `nmemb`：要读取的元素个数。
    - `stream`：指向已打开的 `FILE` 流（必须以读模式打开）。

- **返回值**：

    - 成功时返回**实际读取的元素个数**（类型为 `size_t`）。
    - 若发生错误或到达文件末尾（EOF），返回值可能小于 `nmemb`。
    - 若 `size` 或 `nmemb` 为 0，返回 0。
    - **注意**：无法仅凭返回值区分“读到 EOF”和“发生错误”，需配合 `feof()` 或 `ferror()` 判断。

- **注意事项**：

    1. 不进行格式解析，是**二进制/原始数据读取**（与 `fscanf` 等格式化输入不同）。
    2. 读取的数据直接写入 `ptr` 指向的内存，**不检查边界**，调用者须确保缓冲区足够大。
    3. 若流处于错误状态或未以读模式打开，行为未定义。
    4. 返回值是“元素个数”，不是字节数；总字节数 = `返回值 × size`。



## fwrite()

- **功能简述**：
     将内存中的原始数据按元素写入指定的 `FILE` 流，常用于二进制写入。

- **头文件**：  

    ```c
    #include <stdio.h>
    ```

- **函数原型**：  

    ```c
    size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *stream);
    ```

- **参数说明**：

    - `ptr`：指向要写入数据的内存块起始地址（通常为数组或结构体）。
    - `size`：每个元素的字节大小（如 `sizeof(double)`）。
    - `nmemb`：要写入的元素个数。
    - `stream`：指向已打开的 `FILE` 流（必须以写或追加模式打开，如 `"w"`、`"a"`、`"wb"` 等）。

- **返回值**：

    - 成功时返回**实际写入的元素个数**（类型为 `size_t`）。
    - 若发生写入错误（如磁盘满、流不可写），返回值将小于 `nmemb`。
    - 若 `size` 或 `nmemb` 为 0，函数不执行写操作，返回 0。
    - **注意**：仅当返回值 ≠ `nmemb` 时才可能出错，需结合 `ferror()` 判断是否为错误（而非正常终止）。

- **注意事项**：

    1. 执行的是**原始二进制写入**，不进行格式转换（与 `fprintf` 不同）。
    2. 不检查 `ptr` 指向的内存边界，调用者须确保数据有效且长度足够。
    3. 数据先写入内部缓冲区，不一定立即落盘；可通过 `fflush()` 强制刷新，或在 `fclose()` 时自动刷新。
    4. 若流是以文本模式打开，在某些系统（如 Windows）中可能对换行符 `\n` 进行转换（写成 `\r\n`）。



## fseek()

- **功能简述**：
   将指定 `FILE` 流的文件位置指示器（file position indicator）移动到相对于某个基准点的指定偏移处，用于随机访问文件内容。
  
- **头文件**：  
  
  ```c
  #include <stdio.h>
  ```
  
- **函数原型**：  
  ```c
  int fseek(FILE *stream, long offset, int whence);
  ```

- **参数说明**：
  
  - `stream`：指向已打开的 `FILE` 流（必须可定位，通常为普通文件；对管道、终端等不可定位设备无效）。
  - `offset`：相对于 `whence` 指定位置的字节偏移量（可为正、负或零）。
  - `whence`：起始参考位置，取值必须为以下宏之一：
    - `SEEK_SET`：文件开头
    - `SEEK_CUR`：当前读写位置
    - `SEEK_END`：文件末尾
  
- **返回值**：
  - 成功时返回 `0`。
  - 失败时返回非零值（通常为 `-1`），并设置 `errno`。

- **注意事项**：
  1. 对**文本流**使用 `fseek` 时，`offset` 的值通常应为 `0`，或由 `ftell` 返回的值（C 标准限制：除 `SEEK_SET` 配合 `0` 或 `ftell` 结果外，其他偏移行为未定义）。
  2. 对**二进制流**，`fseek` 支持任意合法偏移。
  3. 调用 `fseek` 会清除流的 `EOF` 标志，并丢弃未读的缓冲输入（对于输入流）。
  4. 若流处于写模式且缓冲区中有数据，`fseek` 会先刷新输出缓冲区。
  5. 在大文件（>2GB）场景下，`long` 可能不足，应考虑使用 `fseeko`（POSIX）或 `_fseeki64`（Windows）等扩展函数。

## perror()

- **功能简述**： 
  根据当前 `errno` 的值，将对应的系统错误信息输出到标准错误流（`stderr`），常用于调试或报告系统调用/库函数失败原因。

- **头文件**：  
  ```c
  #include <stdio.h>
  ```

- **函数原型**：  
  ```c
  void perror(const char *s);
  ```

- **参数说明**：
  - `s`：用户自定义的前缀字符串（通常为出错的函数名或上下文描述）。若为 `NULL` 或空串，则仅输出错误信息本身。

- **返回值**：  
  - 无（`void`）。

- **注意事项**：
  1. 依赖全局变量 `errno`，应在系统调用或标准库函数**刚失败后立即调用**。
  2. 输出格式为：`s: 系统错误描述\n`（如 `"fopen: No such file or directory"`）。
  3. `errno` 仅在函数明确表示失败时才有意义；成功调用不保证 `errno` 为 0。
  4. 在支持 POSIX 的系统中，`errno` 是线程局部的，因此 `perror` 在多线程环境中安全。
  5. 错误消息语言通常由系统 locale 决定（多数系统默认英文）。

# 0x02 目录IO

## opendir()

- **功能简述**： 
    打开一个目录流，用于后续通过 `readdir()` 等函数读取目录内容。

- **头文件**：  

    ```c
    #include <sys/types.h>
    #include <dirent.h>
    ```

- **函数原型**：  

    ```c
    DIR *opendir(const char *name);
    ```

- **参数说明**：

    - `name`：要打开的目录路径名（可以是相对或绝对路径）。

- **返回值**：  

    - 成功时返回指向 `DIR` 类型结构的指针，该指针用于后续目录操作（如 `readdir()`、`closedir()`）；
    - 失败时返回 `NULL`，并设置全局变量 `errno` 以指示具体错误原因（如 `ENOENT`、`ENOTDIR`、`EACCES` 等）。

- **注意事项**：

    1. 调用者必须对该目录具有执行（搜索）权限，否则会失败。
    2. 返回的 `DIR*` 指针不应被直接访问或修改；应仅通过标准目录函数（如 `readdir()`, `rewinddir()`, `closedir()`）使用。
    3. 使用完毕后必须调用 `closedir()` 关闭目录流，以释放相关资源。
    4. `opendir()` 不会递归打开子目录；每次调用仅针对单个目录。
    5. 常配合 `perror()` 或 `strerror(errno)` 进行错误处理。
    6. 该函数是 POSIX 标准的一部分，在 Unix-like 系统（如 Linux、macOS）中广泛支持；Windows 下需使用 `_wfindfirst`/`FindFirstFile` 等 Win32 API 替代。

## closedir()

- **功能简述**： 
    关闭先前由 `opendir()` 打开的目录流，释放相关资源。

- **头文件**：  

    ```c
    #include <sys/types.h>
    #include <dirent.h>
    ```

- **函数原型**：  

    ```c
    int closedir(DIR *dirp);
    ```

- **参数说明**：

    - `dirp`：指向已打开目录流的指针，通常由 `opendir()` 返回。

- **返回值**：  

    - 成功时返回 `0`；
    - 失败时返回 `-1`，并设置全局变量 `errno` 以指示错误原因（如 `EBADF` 表示无效目录指针）。

- **注意事项**：

    1. 每次成功调用 `opendir()` 后，应有且仅有一次对应的 `closedir()` 调用，避免资源泄漏。
    2. 对同一 `DIR*` 多次调用 `closedir()` 的行为未定义，可能导致程序崩溃或错误。
    3. 即使在读取目录过程中发生错误，也应调用 `closedir()` 关闭目录流。
    4. 该函数是 POSIX 标准的一部分，广泛支持于 Unix-like 系统（如 Linux、macOS）。
    5. 若 `dirp` 为 `NULL`，行为未定义，通常会导致段错误，因此不应传入空指针。

## mkdir()

- **功能简述**： 
    创建一个新目录，指定其路径和访问权限。

- **头文件**：  

    ```c
    #include <sys/stat.h>
    #include <sys/types.h>
    ```

- **函数原型**：  

    ```c
    int mkdir(const char *pathname, mode_t mode);
    ```

- **参数说明**：

    - `pathname`：要创建的目录路径名（可以是相对或绝对路径）。
    - `mode`：指定新目录的权限位（如 `0755`、`0644` 等），实际生效权限会受进程的 `umask` 影响。

- **返回值**：  

    - 成功时返回 `0`；
    - 失败时返回 `-1`，并设置全局变量 `errno` 以指示具体错误原因（如 `EEXIST`、`ENOENT`、`EACCES` 等）。

- **注意事项**：

    1. 若 `pathname` 中包含的父目录不存在，则 `mkdir` 会失败（不会递归创建目录）。
    2. 权限 `mode` 参数仅在创建成功时生效；若目录已存在，不会修改其权限。
    3. 在类 Unix 系统中，调用者必须对父目录具有写和执行权限。
    4. 该函数是 POSIX 标准的一部分，在大多数 Unix-like 系统（包括 Linux 和 macOS）中可用；Windows 下需使用 `_mkdir()`（来自 `<direct.h>`）。
    5. 常配合 `perror()` 或 `strerror(errno)` 用于错误诊断。

## readdir()

- **功能简述**： 
    从已打开的目录流中读取下一个目录项，返回包含文件名等信息的结构体指针。

- **头文件**：  

    ```c
    #include <sys/types.h>
    #include <dirent.h>
    ```

- **函数原型**：  

    ```c
    struct dirent *readdir(DIR *dirp);
    ```

- **参数说明**：

    - `dirp`：指向已打开目录流的指针，由 `opendir()` 返回。

- **返回值**：  

    - 成功时返回指向 `struct dirent` 类型的指针，表示当前读取到的目录项；
    - 到达目录末尾或发生错误时返回 `NULL`。  
      注意：无法仅凭返回 `NULL` 区分是结束还是出错，需检查 `errno`（调用前应先清零 `errno`）。

- **注意事项**：

    1. `readdir()` 每次调用读取一个目录项，内部维护读取位置，多次调用可遍历整个目录。
    2. 返回的 `struct dirent` 对象由系统管理，其内容在下次调用 `readdir()`、`rewinddir()` 或 `closedir()` 后可能被覆盖，如需保留应复制内容。
    3. 常见成员包括：
       - `d_name`：目录项的文件名（以 null 结尾的字符串）；
       - 其他成员（如 `d_ino`、`d_type`）是否有效取决于具体系统实现。
    4. 若需区分“读取完毕”和“发生错误”，建议在调用前设置 `errno = 0`，调用后若返回 `NULL` 且 `errno != 0`，则表示出错。
    5. 该函数是 POSIX 标准的一部分，在 Unix-like 系统中广泛支持；非线程安全（多线程环境下应使用 `readdir_r()`，但注意后者在较新 POSIX 版本中已被弃用，推荐使用线程局部 `DIR*` 实例）。

## stat()

- **功能简述**： 
    获取指定文件或目录的元数据（如类型、大小、权限、时间戳等），通过路径名访问。

- **头文件**：  

    ```c
    #include <sys/stat.h>
    #include <unistd.h>
    ```

- **函数原型**：  

    ```c
    int stat(const char *pathname, struct stat *buf);
    ```

- **参数说明**：

    - `pathname`：目标文件或目录的路径名（可以是相对或绝对路径）。
    - `buf`：指向 `struct stat` 类型的指针，用于接收文件状态信息。

- **返回值**：  

    - 成功时返回 `0`；
    - 失败时返回 `-1`，并设置全局变量 `errno` 以指示具体错误原因（如 `ENOENT`、`EACCES`、`ENOTDIR` 等）。

- **注意事项**：

    1. 若 `pathname` 是符号链接，`stat()` 会自动解引用，返回链接所指向文件的信息；若需获取链接本身的信息，应使用 `lstat()`。
    
    2. 常用的 `struct stat` 成员包括：
       - `st_mode`：文件类型和权限（可用 `S_ISDIR()`、`S_ISREG()` 等宏判断类型）；
       
       - `st_size`：文件字节大小（对普通文件有效）；
       
       - `st_mtime`、`st_atime`、`st_ctime`：修改、访问、状态变更时间。
       
       - 具体定义如下
       
           ```c
           struct stat {
               dev_t     st_dev;         // 文件所在设备的设备号
               ino_t     st_ino;         // 文件的 inode 编号
               mode_t    st_mode;        // 文件类型和权限位
               nlink_t   st_nlink;       // 硬链接数量
               uid_t     st_uid;         // 文件所有者的用户 ID
               gid_t     st_gid;         // 文件所有者的组 ID
               dev_t     st_rdev;        // 若为设备文件，表示设备号（主/次设备号）
               off_t     st_size;        // 文件字节大小（对普通文件、部分特殊文件有效）
               time_t    st_atime;       // 最后访问时间（已弃用，建议使用 st_atim）
               time_t    st_mtime;       // 最后修改时间（已弃用，建议使用 st_mtim）
               time_t    st_ctime;       // 最后状态变更时间（如权限、属主改变；非创建时间）
               blksize_t st_blksize;     // 文件系统 I/O 的最佳块大小
               blkcnt_t  st_blocks;      // 分配给文件的 512 字节块数（可能不等于 st_size / 512）
               // 以下为 timespec 类型（若支持 nanosecond 精度）：
               struct timespec st_atim;  // 纳秒级最后访问时间
               struct timespec st_mtim;  // 纳秒级最后修改时间
               struct timespec st_ctim;  // 纳秒级状态变更时间
               // 可能还有其他实现相关字段（如 macOS 的 st_flags, st_gen 等）
           };
           ```
       
    3. 调用进程必须对路径中所有上级目录具有执行（搜索）权限，且对目标文件（或其父目录）具有适当权限才能读取元数据。
    
    4. 该函数是 POSIX 标准的一部分，在 Unix-like 系统（如 Linux、macOS）中广泛支持。
    
    5. 成功调用后，`buf` 所指结构体的内容有效；失败时其内容未定义。

## access()

- **功能简述**： 
    检查调用进程对指定文件或目录是否具有某种访问权限（如读、写、执行），基于实际用户/组 ID 而非有效 ID。

- **头文件**：  

    ```c
    #include <unistd.h>
    ```

- **函数原型**：  

    ```c
    int access(const char *pathname, int mode);
    ```

- **参数说明**：

    - `pathname`：要检查权限的文件或目录路径名（可以是相对或绝对路径）。
    - `mode`：指定要测试的权限类型，可为以下常量的按位或组合：
      - `F_OK`：仅检查文件是否存在；
      - `R_OK`：检查是否可读；
      - `W_OK`：检查是否可写；
      - `X_OK`：检查是否可执行（对目录表示可搜索）。

- **返回值**：  

    - 若指定的访问权限全部满足，返回 `0`；
    - 若任一权限不满足或发生错误，返回 `-1`，并设置全局变量 `errno`（如 `ENOENT`、`EACCES` 等）。

- **注意事项**：

    1. `access()` 使用**实际用户 ID 和实际组 ID** 进行权限检查，而非有效 ID，因此常用于 set-user-ID 或 set-group-ID 程序中判断普通用户是否有权访问某文件。
    2. 存在“检查-使用”（Time-of-check to time-of-use, TOCTOU）竞态条件风险：即使 `access()` 返回成功，后续真正操作文件时权限状态可能已改变，因此不应依赖它来做安全决策。
    3. 对符号链接会自动解引用，检查其目标文件的权限。
    4. 该函数是 POSIX 标准的一部分，在 Unix-like 系统中广泛支持。
    5. 成功仅表示“理论上可访问”，不代表后续操作一定成功（例如磁盘满、文件被删除等运行时问题仍可能发生）。

## chmod()

- **功能简述**：  
    修改指定文件或目录的权限位（即访问权限），如读、写、执行权限。

- **头文件**：  

    ```c
    #include <sys/stat.h>
    ```

- **函数原型**：  

    ```c
    int chmod(const char *pathname, mode_t mode);
    ```

- **参数说明**：

    - `pathname`：目标文件或目录的路径名（可以是相对或绝对路径）。
    - `mode`：新的权限模式，通常以八进制常量表示（如 `0644`、`0755`），也可通过 `S_IRUSR`、`S_IWGRP` 等宏组合构造。

- **返回值**：  

    - 成功时返回 `0`；
    - 失败时返回 `-1`，并设置全局变量 `errno` 以指示具体错误原因（如 `ENOENT`、`EACCES`、`EPERM` 等）。

- **注意事项**：

    1. 调用者必须是文件的所有者或具有超级用户（root）权限，否则操作将失败（`EPERM`）。
    2. 权限修改仅影响文件的 `st_mode` 字段中的权限位，不影响其他元数据（如时间戳）。
    3. 若 `pathname` 是符号链接，`chmod()` 会作用于链接所指向的目标文件（而非链接本身）；大多数系统不支持直接修改符号链接的权限。
    4. 实际生效的权限可能受文件系统特性限制（如 FAT 不支持 Unix 权限）。
    5. 该函数是 POSIX 标准的一部分，在 Unix-like 系统（如 Linux、macOS）中广泛支持。
    6. 常用于程序创建临时文件后调整其访问控制，以增强安全性（例如设置为仅所有者可读写）。

## unlink() 系统调用

- **功能简述**：
      删除一个文件的目录项（即“删除文件”），若该文件无其他硬链接且未被打开，则其数据将被释放。

- **头文件**：  

    ```c
    #include <unistd.h>
    ```

- **函数原型**：  

    ```c
    int unlink(const char *pathname);
    ```

- **参数说明**：

    - `pathname`：要删除的文件路径名（必须是普通文件或符号链接，不能是目录）。

- **返回值**：  

    - 成功时返回 `0`；
    - 失败时返回 `-1`，并设置全局变量 `errno` 以指示具体错误原因（如 `ENOENT`、`EISDIR`、`EACCES`、`EPERM` 等）。

- **注意事项**：

    1. `unlink()` 仅删除路径名与文件 inode 之间的链接。只有当文件的硬链接计数降为 0 **且** 没有进程打开该文件时，文件数据才会真正被释放。
    2. 不能用于删除目录（尝试删除目录会失败并置 `errno` 为 `EISDIR`）；删除目录应使用 `rmdir()`。
    3. 若文件正被某个进程打开，`unlink()` 仍可成功删除其目录项，但文件内容会保留至所有打开描述符关闭后才被系统回收（常用于创建临时匿名文件）。
    4. 对符号链接调用 `unlink()` 会删除链接本身，而非其指向的目标文件。
    5. 调用者需对包含该文件的目录具有写和执行权限。
    6. 该函数是 POSIX 标准的一部分，在 Unix-like 系统中广泛支持。

## remove() 库函数

- **功能简述**： 
    通用文件/目录删除函数：若参数为普通文件或符号链接，则等价于 `unlink()`；若为目录，则等价于 `rmdir()`。

- **头文件**：  

    ```c
    #include <stdio.h>
    ```

- **函数原型**：  

    ```c
    int remove(const char *pathname);
    ```

- **参数说明**：

    - `pathname`：要删除的文件或空目录的路径名（可以是相对或绝对路径）。

- **返回值**：  

    - 成功时返回 `0`；
    - 失败时返回 `-1`，并设置全局变量 `errno` 以指示具体错误原因（如 `ENOENT`、`EACCES`、`ENOTEMPTY`、`EISDIR` 等）。

- **注意事项**：

    1. `remove()` 是 C 标准库函数（ISO C），具有良好的可移植性。
    2. 对于**文件或符号链接**，内部调用 `unlink()`；对于**目录**，内部调用 `rmdir()`。
    3. 不能删除非空目录（与 `rmdir()` 行为一致），尝试删除非空目录将失败并置 `errno` 为 `ENOTEMPTY` 或 `EEXIST`。
    4. 若 `pathname` 指向一个被打开的文件，行为取决于系统：在 POSIX 系统上通常允许删除（类似 `unlink()`），但文件数据保留至所有引用关闭。
    5. 不支持递归删除目录树；如需递归删除，必须自行遍历并逐个删除内容。
    6. 尽管声明在 `<stdio.h>` 中，但其操作属于文件系统管理，不涉及标准 I/O 流。

## rename()

- **功能简述**： 
    重命名文件或目录，或将其移动到同一文件系统内的另一个位置。

- **头文件**：  

    ```c
    #include <stdio.h>
    ```

- **函数原型**：  

    ```c
    int rename(const char *oldpath, const char *newpath);
    ```

- **参数说明**：

    - `oldpath`：现有文件或目录的路径名。
    - `newpath`：新的路径名（可以是新名称或新位置）。

- **返回值**：  

    - 成功时返回 `0`；
    - 失败时返回 `-1`，并设置全局变量 `errno` 以指示具体错误原因（如 `ENOENT`、`EEXIST`、`ENOTEMPTY`、`EXDEV` 等）。

- **注意事项**：

    1. 若 `newpath` 已存在且为普通文件，则在 POSIX 系统上会被**原子地覆盖**（先删除再重命名），但若为非空目录则操作失败。
    2. `rename()` 仅在同一文件系统内有效；若 `oldpath` 和 `newpath` 位于不同文件系统，调用将失败并置 `errno` 为 `EXDEV`。
    3. 对目录进行重命名时，`newpath` 不能是现有目录（即使为空），除非系统特别允许（POSIX 要求 `newpath` 若存在必须是普通文件）。
    4. 该操作是原子的：要么完全成功，要么完全不生效，适合用于实现安全的文件更新（如写入临时文件后 rename 覆盖原文件）。
    5. 符号链接本身可被重命名，但不会影响其指向的目标。
    6. 作为 ISO C 标准函数，`rename()` 具有良好的跨平台可移植性，但在不同系统上对目录和跨设备行为的支持可能略有差异。
